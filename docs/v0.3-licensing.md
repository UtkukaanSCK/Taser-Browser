# Taser v0.3: licensing of the first-run ad blocker

> This is not legal advice. It is our own reading of the licences.

## Summary

- **Taser** is MIT-licensed (see `LICENSE`).
- **uBlock Origin Lite (uBOL)** is GPLv3.
  - Source: <https://github.com/uBlockOrigin/uBOL-home>
  - Licence text: <https://github.com/uBlockOrigin/uBOL-home/blob/main/LICENSE>
- Taser does **not** hold a copy of uBOL, redistribute it or modify it. Neither the repository nor the release binary contains any uBOL code.
- The filter lists that uBOL ships and uses have their own licences, set by each list's authors. Taser does not touch them.

## How uBOL arrives

Taser itself downloads and installs uBOL from the Chrome Web Store on the first start that has a data folder. It does this without asking, through task 4's store install path.
- Extension id: `ddkjiahejlhfcafbddmgiahcphecmpfh`
- The package is the store's signed CRX, fetched at run time from the store.
- It goes into the WebView2 profile unchanged. Taser keeps no copy of its own, ships none and changes nothing in it.

Taser downloads the publisher's own package from the publisher's distribution channel at run time. It does not ship a GPLv3 work in its own distribution, so its MIT licence is unaffected. The two programs talk only through the standard extension API: Taser installs, lists and removes the extension, and does not link against uBOL.

## User control

The state lives in `extensions.json` under `first_run_ubol`:
- `pending`: not installed yet. Try again on the next start.
- `done`: installed once. Never fetched again by the first-run logic.
- `user_removed`: the user removed uBOL.

**Removal is permanent.** When the user removes uBOL, the state becomes `user_removed`, and Taser never installs it again on its own. The user can still install it themselves from the store.
- The extensions page, where users remove extensions, arrives in task 5.
- If the user removes uBOL while the first-run install is still running, the state is still `user_removed`. The install lands once and Taser takes it back out.
- Removals Taser makes for its own reasons, such as taking back an install that failed, do not count as the user's choice.

The first-run install happens without a confirmation dialog. This is why the removal choice must stick.

Known cases where `user_removed` is lost and uBOL may be installed once more:
- **Going back to an older build.** A build from before this field already keeps `extensions.json` but does not know `first_run_ubol`. Its next save writes the file without the field, which then reads as `pending`. v0.2 itself has no `extensions.json` and leaves the state alone.
- **A damaged main file with an old `.bak`.** If `extensions.json` is damaged, the state is read from `extensions.json.bak`. A `.bak` from before the removal holds `pending` (or `done`).
- **Both files lost.** If both are gone, the state falls back to `pending`.
