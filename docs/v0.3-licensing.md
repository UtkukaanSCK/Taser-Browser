# X-Browser v0.3: licensing of the first-run ad blocker

## Summary

- **X-Browser** is MIT-licensed (see `LICENSE`).
- **uBlock Origin Lite (uBOL)** is GPLv3.
  - Source: <https://github.com/uBlockOrigin/uBOL-home>
  - Licence text: <https://github.com/uBlockOrigin/uBOL-home/blob/main/LICENSE>
- X-Browser does **not** bundle, modify or redistribute uBOL. The repository, the release binary and the installer contain no uBOL code.

## How uBOL arrives

On the first start that has a data folder, X-Browser asks the WebView2 profile to install uBOL from the Chrome Web Store, using the same store install path as a user-initiated install.
- Extension id: `ddkjiahejlhfcafbddmgiahcphecmpfh`
- The package is the store's signed CRX, downloaded at run time by the user's own browser.
- X-Browser does not change the package or ship a copy of it.

Because uBOL is fetched by the end user from its publisher's distribution channel, X-Browser is not distributing a GPLv3 work. Its MIT licence is unaffected. The two programs talk only through the standard extension API: X-Browser installs, lists and removes the extension, and does not link against uBOL.

## User control

The state lives in `extensions.json` under `first_run_ubol`:
- `pending`: not installed yet. Try again on the next start.
- `done`: installed once. Never fetched again by the first-run logic.
- `user_removed`: the user removed uBOL.

**Removal is permanent.** When the user removes uBOL from the extensions page, the state becomes `user_removed`, and X-Browser never installs it again on its own. The user can still install it themselves from the store.

The first-run install happens without a confirmation dialog. This is why the removal choice must stick.

Known edge case: if both `extensions.json` and `extensions.json.bak` are lost, the state falls back to `pending`. uBOL is then installed once more, even after an earlier removal.
