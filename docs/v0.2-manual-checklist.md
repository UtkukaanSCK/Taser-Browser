# v0.2 manual checklist

What the in-app self-test (`--features selftest`) cannot prove. It drives the
app from inside, never starts other applications, and cannot see or press keys
in WebView2's browser-process windows (flyouts, bubbles, the find bar). Run
this list on a release build (`cargo build --release`) before v0.2 ships.

Use a scratch profile unless a step says otherwise: point `LOCALAPPDATA` and
`APPDATA` at an empty folder for the command that starts
`target\release\taser.exe`.

For each line, write the date, the Windows/WebView2 version and OK or what
went wrong.

## Downloads

- [ ] Download a real file (any small file from a known site). WebView2's
      flyout opens at the top right of the page area: progress, then
      "open file" / "open folder". It looks right, light and dark theme.
- [ ] The strip's downloads button appears after the first download; Ctrl+J,
      the button and the menu item each open and close the flyout.
- [ ] "Open file" opens the downloaded file in its application; "open folder"
      opens Explorer with the file selected.
- [ ] SmartScreen: download a known test file flagged by SmartScreen (for
      example Microsoft's SmartScreen demo page). The warning appears and
      the file is not saved silently.
- [ ] Download folder set in settings: the next download lands there.
- [ ] Setting the download folder to the Startup folder
      (`shell:startup`, and `shell:common startup`, also a subfolder of
      either, with other letter case or a trailing `\`) is refused with the
      "folder-bad" message. Known gap: an 8.3 short name or a junction that
      points into Startup is not recognised.

## Settings across a restart

- [ ] Change every setting (engine, startup "blank tab", autofill off, a
      download folder), close Taser, start it again: all four are kept
      and in force (a search uses the chosen engine; one blank tab opens;
      a login form offers no autofill; a download goes to the folder).
- [ ] Put the startup setting back to "last session": the tabs of the last
      run come back.
- [ ] Edit `settings.json` by hand to an unknown engine name: that one value
      reads as the default, the others stay.

## Certificate errors

- [ ] Open a real bad-certificate site (for example `https://expired.badssl.com/`
      and `https://self-signed.badssl.com/`). WebView2's warning page shows;
      the address box says "Sertifika hatası".
- [ ] Choose to proceed on the warning page. The site loads and the mark
      still says "Sertifika hatası", also after a reload, in a new tab and
      on another port of the same host.
- [ ] Another https site in the same run still gets the lock.
- [ ] After a restart the host gets its warning page again (the memory is
      per run).

## External applications (launch question)

Only on a machine where starting these applications is expected.

- [ ] Click a `mailto:` link: the question shows the scheme, the asking site
      and the whole address. "Aç" pressed at once does nothing; after a short
      pause it opens the mail application.
- [ ] Same for a `tel:` link (opens the phone/calling application, or
      Windows' "choose an app" if there is none).
- [ ] An `ms-windows-store:` link opens the Store page after "Aç".
- [ ] An `ms-settings:` link (or any other `ms-` scheme) shows no question
      and opens nothing.
- [ ] Esc, a click on the page, a tab switch, ⋮ and 60 s of waiting each
      answer "no".
- [ ] Two launches in a row from a background tab (a page that opens a
      `mailto:` link twice after a timer while another tab is active): no
      question appears for a tab that is not on screen (only the active tab
      may ask), and nothing is started. Return to the tab: still nothing
      starts by itself.
- [ ] Two launches in a row while the Taser window is behind another
      application (same timer page, then switch to another window): the
      question does not steal focus or start anything; on coming back there
      is at most one question, and a second request while one is up answers
      the first "no".
- [ ] In a narrow window (about 500 px wide) the question still fits and
      "Aç" is reachable. Known limit: there its position barely changes from
      one question to the next.

## Screen reader (Narrator, and NVDA if available)

- [ ] Launch question: on appearing, the reader says it is a question and
      reads the scheme, the site and the address; Tab reaches "Aç" and
      "İptal", each read by name.
- [ ] Menu (⋮, Alt+F): the reader announces a menu and reads each item while
      ↑/↓ move; Enter picks; Esc closes and focus returns where it was.
- [ ] Clicking ⋮ while the launch question is up: the question closes
      ("no"), the menu opens and the arrow keys work at once.
- [ ] Security indicator: moving between an http page, an https page and a
      bad-certificate page, the change is read out once each.
- [ ] After more than 64 bad-certificate hosts in one run (a local test
      server is the practical way), "Sertifikalara güvenilmiyor" is read out
      once, with no dialog.

## Crashed tab

- [ ] Crash a tab's renderer (open `edge://kill` in it if WebView2 allows,
      or end its renderer process in Task Manager). The indicator says
      "Sayfa çöktü" and a "Yeniden yükle" button appears.
- [ ] From the address box, Tab reaches "Yeniden yükle" by keyboard; Enter
      or Space reloads the page and the crash mark goes away.

## Overlay at another scale and across monitors

- [ ] At 125 % and 150 % display scale: suggestions, history, bookmarks,
      menu, settings and the launch question sit under the strip, aligned,
      with no cut-off text or blurred edges.
- [ ] With two monitors at different scales: open each overlay, then drag
      the window to the other monitor. The overlay closes on the move and
      opens in the right place on the new monitor.
- [ ] Bookmarks star (☆): clicking it while its editor is open closes the
      editor (does not reopen it).

## Esc in WebView2's own windows

- [ ] Ctrl+F, type a word, press Esc while the find bar has focus: the find
      bar closes. Same with focus back in the page.
- [ ] Known limit: after moving the window, note where the find bar is (it
      is a separate window; whether it follows is not verified).
- [ ] A geolocation or camera permission bubble: Esc while it has focus
      closes it (as "block" or "dismiss"), and the page is not granted.

## Notification permission prompt alone

- [ ] On a page that calls `Notification.requestPermission()` with no other
      bubble open: note whether WebView2 shows a bubble or answers `denied`
      at once (earlier probes only saw it with another bubble already open).

## Elevated (administrator) instance

- [ ] Start Taser as administrator, then start it normally with an
      address. The normal start does not open a second copy beside it: it
      shows "Taser zaten açık, ancak bu başlatma ona bağlanamadı (farklı
      yetki düzeyi ya da yanıt vermiyor)." and exits. (Windows UIPI blocks the
      hand-over to the higher-integrity window.)
- [ ] The reverse (normal first, then elevated) does not run two copies
      either.

## File dropped from outside

- [ ] Drag a file from Explorer onto a page: the tab does not navigate to
      `file://`, no tab or window opens.
- [ ] Drop a file onto a page's own drop zone or `<input type=file>`
      (for example an upload form): the page receives it.
- [ ] Drag a file onto the tab strip and the address box: nothing happens,
      nothing opens.

## History and suggestions

- [ ] With the history list (Ctrl+H) open, a page that changes only its
      `#fragment` (an in-page link) leaves the list open.
- [ ] Reload the same page several times quickly: it counts as one visit
      for "often" ranking.
